# Heu-Supporter

Heu-Supporter は、ヒューリスティックコンテスト向けのローカル支援ツールです。  
`tools.zip` を読み込んでコンテストごとの作業環境を作り、コード編集、提出実行、ケース分析、統計確認、定数調整までを 1 つのデスクトップアプリでまとめて行えます。

## このツールでできること

### 1. コンテストをまとめて管理できる

- `tools.zip` から新しいコンテスト環境を作成できます
- コンテストごとに提出、統計、生成済みケース、設定を分けて保持できます
- 一覧画面からコンテストの作成日時や更新日時を見ながら管理できます
- 不要なコンテストは削除できます
- コンテストをアーカイブできます
  - seed ごとの入出力、提出コード、生成データなどの重いファイルを削除します
  - 提出一覧、点数、統計などの軽い情報は残るので、後から結果だけ見返せます

### 2. ローカルでコードを書いてそのまま実行できる

- エディタ上で提出コードを編集できます
- `C++`、`Rust`、`Python` など複数言語に対応できます
- コンテストごとにコードや言語の状態を保持できます
- 提出回数を指定してまとめて実行できます
- 他の提出が動いている間でも追加提出できます
  - 待機中の提出は `WJ` として表示されます
  - 先行提出が終わると順番に自動で実行されます
- 実行待ち中でも実行中でもキャンセルできます

### 3. 特定ケースだけを狙って試せる

- お気に入りケースだけを対象にした提出ができます
  - 実行回数を `n`、お気に入り数を `m` とすると `min(n, m)` 件だけ実行します
- 変数条件でケースを絞り込んだ提出ができます
  - 条件に合うケースを集めて、指定回数に達するまで増やします
  - 30 秒以内に十分集まらなければ、その時点で集まったケースだけで実行します
- こうした特殊実行は正規スコアではない可能性が高いため、提出一覧や詳細で通常提出と区別して表示されます

### 4. 実行結果をケース単位で詳しく見られる

- 提出ごとの総合スコア、相対スコア、結果を一覧で確認できます
- `AC` だけを比較対象にした相対スコア計算を行います
  - `WA` や `RE` や `TLE` の `0` 点が比較を壊さないようになっています
  - `AC` の `0` 点はそのまま扱います
- 各提出について、ケースごとの結果、得点、相対スコアを確認できます
- 実行結果詳細では、どのケースで強いかを見やすく追えます
- `ユニークケース数` を確認できます
  - その提出が相対スコア最大になっているケース数です
- ケースごとにお気に入り登録できます
- ケースごとの入出力や可視化結果を開けます

### 5. 提出の比較と絞り込みがしやすい

- 提出一覧を得点、相対スコア、日時、結果などでソートできます
- 提出にもお気に入りを付けられます
- 提出お気に入りだけを表示できます
- 実行結果詳細から一覧へ戻りやすい UI になっています
- 統計タブの提出名を押すと、その提出の実行結果詳細へ直接移動できます

### 6. 統計タブで傾向を分析できる

- 複数提出を並べて比較できます
- 上部の提出一覧をソートしながら比較対象を選べます
- `seed` を横軸にしたスコアグラフを常に上部に表示できます
- その下に、各変数を横軸にしたグラフを並べて確認できます
- 絶対スコアと相対スコアを切り替えて見られます
- 次のような絞り込みができます
  - seed 範囲
  - お気に入りケースのみ
  - スコア条件
  - 変数条件
- 統計から選んだ提出の詳細へそのまま飛べます

### 7. 定数チューニングを支援できる

- ソースコード中の定数候補を検出できます
- 定数を書き換えながら複数パターンを実行できます
- チューニング結果の履歴を残して比較できます
- どの設定が良かったかをあとで見返せます

### 8. ビジュアライザと連携できる

- ローカルにある可視化ツールをアプリから開けます
- ケースごとの出力をそのまま流して確認できます
- AtCoder Heuristic Contest 系の `webvis` / ローカルビジュアライザ運用をしやすくします

## こんな使い方に向いています

- AHC のローカルテストと結果管理を 1 か所にまとめたい
- seed ごとの強いケース、弱いケースをすぐ見たい
- お気に入りケースだけで高速に試したい
- 変数ごとの傾向をグラフで見たい
- 定数調整の履歴を残しながら比較したい
- 過去コンテストを重いデータなしで保存しておきたい

## 動作に必要なもの

コンテストの `tools.zip` に含まれるツールや、使う提出言語に応じてローカル環境が必要です。

- `Node.js` / `npm`
- `Rust` / `cargo`
- `g++` などの C++ コンパイラ
- `python3`
- そのコンテストで必要なビルドツールやランタイム

## 開発環境の立ち上げ

```bash
git clone https://github.com/potatoo1211/heu-supporter.git
cd heu-supporter
npm install
npm run tauri dev
```

配布用ビルド:

```bash
npm run tauri build
```

## 使い始め

1. アプリを起動して `tools.zip` を参照し、コンテストを作成します
2. 提出コードを書いて実行します
3. 提出一覧と詳細でケースごとの結果を確認します
4. 必要に応じてお気に入りケース実行や変数絞り込み実行を使います
5. 統計タブで提出同士の違いを分析します
6. 終わったコンテストはアーカイブして軽量化できます
